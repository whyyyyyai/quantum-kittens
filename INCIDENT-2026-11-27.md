## What I did to recover

1. Read the journal of the crashed boot:
   `journalctl -b -1 --no-pager | tail` and
   `journalctl -b -1 | grep -iE 'oom|gpu|timeout|fault|panic|killed'`.
2. Ran `~/launch-codes/launch.sh --dry-run`, then `~/launch-codes/launch.sh`.
   The services were running, swap was on, and every self-test passed
   (comms-deck, scratchpad-layout, hypr-recover, nav-deck).
3. Opened Grok:
   `PATH="$HOME/.grok/bin:$PATH" ~/quantum-kittens/launcher/launch-desktop`.
   The login service's PATH doesn't include `~/.grok/bin`, and PR #15 in
   this repo, which fixes that, is still open.
4. Ran `~/launch-codes/snapshot.sh --check` to list work at risk (below).
5. Found that launch-codes held an old `hyprland.lua` (the comms/nav/mail
   layout from 26 Nov), so a `--force` restore would have put back the old
   desks. Saved the machine's copy with `snapshot.sh` and updated the desks
   table: launch-codes PR #5.

The warp core wasn't restarted. It's on its first start of this boot and
climbing (10 fps while hidden right after login, 29.6 fps at 17:06).

## Cause

warp-core stalled the GPU. No driver fault was logged, so it wasn't a
crash in the kernel's eyes, but frames timed out for half a minute and the
screen became sluggish or frozen. Restarting warp-core repeatedly is what
pushed the GPU over on the morning of the 27th, and this afternoon it had
been restarted four times in under an hour by installs.

The `gpu-ok.sh` guard only blocks a start after a kernel GPU timeout or
crash. App-level swap-chain timeouts don't trip it, so it let this one
through.

## Next time: recovery checklist

1. **Log in.** Hyprland should load the full config. If it comes up in
   safe mode (stock look, no bar), follow "Outage recovery" in
   `~/comms-deck/quantum-kittens.md`, or run hypr-recover.
2. **Run `~/launch-codes/launch.sh`**. It's safe to repeat and never
   discards work. Read every `!` line. Known, harmless ones today:
   - `load-balancer is on 'devin/join-window'`: devin's live tree.
   - `comms-deck/deck: no Cargo.toml`: the Rust deck isn't on `test` yet.
   - `grok is not installed, skipped`: open Grok with the PATH line in
     step 3 above until PR #15 is merged.
3. **Find the cause before restarting anything GPU-heavy:**
   `journalctl -b -1 --no-pager | grep -E 'swap chain|health|Power key|oom|panic'`.
   If warp-core was stalling, leave it alone. Don't restart it in a loop.
4. **Check for work at risk:** `~/launch-codes/snapshot.sh --check`. Tell
   each owner about their own lines; never commit another seat's work.
5. **Tell Y** on the chat screen (`send_message` to `owner`) what came
   back and what didn't.
6. **File it**: one dated section in `~/comms-deck/quantum-kittens.md`, or
   an `INCIDENT-<date>.md` here for anything bigger.

## Suggestions (not done; for Y to choose)

- **Install warp-core less often.** Batch merges and install once, as vibe
  already proposes for #152 and #158. Each restart re-creates the Bevy
  window on the GPU.
- **Make the guard see stalls.** warp-core could count swap-chain timeouts,
  and above a threshold (for example 10 in a minute) drop to a lighter
  look or exit with a status that gpu-ok.sh honours, before the desktop
  freezes.
- **Snapshot after every layout change**, not only before shutdowns, so
  launch-codes never holds an old desktop.
- **Merge quantum-kittens #15** so Grok opens at login.
